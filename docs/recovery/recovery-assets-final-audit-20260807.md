# SR1010 当前固件恢复资产最终离线审计

日期：2026-08-07

## 当前实机全闪存备份

两份独立保存的当前实机备份逐字节一致：

```text
size   = 134217728
sha256 = efe0c1b7bf98bd53fd2cb12a6dee75577c62b80207ca1113965b8f352c961710
```

双槽common header CRC、slot header CRC和boot prefix CRC均通过。当前槽与备用槽只有槽地址、
计数/头CRC及6个JFFS2擦除块存在预期差异；kernel和基础rootfs版本相同。

## 重建网页升级包

用统一工具从当前全闪存重新生成网页候选包并通过独立预检：

```text
size      = 31851284 (0x1e60314)
sha256    = 51dcbd7eba797bff39dd545bfc7534543068cff5e5727893eb508c88b219a7a5
version   = V1.0.0.2B5.8000

```

该候选包含设备当前JFFS2内容，只保存在本地分析目录，不提交Git，也未上传路由器。

## 原始NAND旧转储复核

旧`dump_raw.bin`按2048+64 OOB剥离后与旧`dump.bin`仅相差3字节、分布在3页，且没有坏块
标记。这符合读取/ECC修正差异，而不是大范围错位。旧转储SHA-256与2026-08-07当前实机
转储不同，因此旧文件只作为历史底层样本，不替代当前恢复基线。

## 当前可用程度

- 当前128MiB全闪存：完整底层恢复基线；
- 当前网页包：格式、三层CRC、产品/version和零签名边界均已离线通过；
- config.bin：已有解密、审计、重打包和实机恢复闭环；
- 双槽：目标槽、计数、切换和回滚字段已还原；
- 原始NAND：OOB剥离和坏块检查工具已验证。

物理救砖仍需要能够接触NAND/Bootloader的写入通道；“恢复资产完整”不等于远程任意写入
一定安全。当前审计没有进行刷写或重启。
