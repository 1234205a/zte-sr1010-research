# SR1010 实机升级状态只读核验

日期：2026-08-07  
连接：WireGuard 内网到 `192.168.50.1` 的现有 LAN Telnet；只执行 procfs 读取，没有写配置、
写 MTD、触发升级或重启。

## 当前设备值

从 `/proc/csp/versionstates` 实机读取并用
[`tools/upgrade-key-readonly.py`](tools/upgrade-key-readonly.py) 复核：

```text
curUpgradeKey1 = 0x00000510
curUpgradeKey2 = 0x00000001
```

当前 key1 不是 `0`/`0xffff` 哨兵值。因此，对普通非哨兵升级头，本机实际要求包内
`upgrade_key1=0x510` 且 `upgrade_key2=1`；只匹配其中一个会返回升级 key 错误。

如果某种兼容升级头允许包内 key1 使用 `0` 或 `0xffff`，按已还原的 cspd 控制流会跳过
两个 key 的比较。但在外层头格式恢复完成前，不据此生成或导入候选包。

## 同时确认的运行时字段

该 procfs 节点还直接暴露当前/备用固件状态，包括物理地址、头地址、序列号、当前槽标志、
坏槽标志、JFFS 标志、签名长度、固件格式/类型及最大版本数。原始快照留在本机分析目录，
不提交仓库；仓库只记录这次已经核实、可复现的升级 key 结论。

- 将来取得原厂升级包后，可以立即检查其 key 是否适配本机。
- 可以继续只读利用同一节点核对双槽状态，无需读取 NAND 或重启设备。
